## M4 — Core runtime re-architecture & hardening (`D12`–`D17`, `D21`–`D28`, `D38`, `EC02`, `EC04`, `EC06`–`EC40`)

Scheduled after `M7` (`D28`, targeting the next `0.x` release after the initial `v0.1.0` baseline). Internal sequence is binding: `M4.1` and `M4.2` establish the in-memory store, event-targeted capture, and surgical `#naizodb` disk sync so `M4.3` bindings and list controls are implemented once on top of the store.

- [x] **M4.1 — In-memory store, synchronous boot, and `O(1)` event-targeted capture (`D12`, `D15`, `D21`–`D23`, `D27`; `EC04`, `EC06`, `EC11`, `EC14`–`EC16`, `EC18`–`EC25`, `EC32`–`EC35`, `EC38`)** (landed 2026-10-21):
  - Built one in-memory `NaizoDatabase` (`{ _meta, fields, lists, custom }`) in `initNaizo()`, validating root/bucket/item shapes (`EC33`) and installing all four buckets from resolved disk or `localStorage` cache before hydrating or firing `naizo:hydrate` (`EC32`). When startup `#naizodb` has a JSON syntax or shape error (`EC04`, `EC33`), preserves the raw script text, surfaces an error state (`Invalid #naizodb JSON`) in the status pill, and blocks automatic write-back until resolved.
  - Attached delegated `input` / `change` / `click` listeners synchronously before awaiting IndexedDB handle lookup (`EC34`), and wrapped all `localStorage` / `indexedDB` accesses in `try/catch` so blocked storage or quota errors never break in-memory operation (`EC22`).
  - Routed `O(1)` event capture from `event.target` to its bound scalar key or `[naizo-item]` row object (`WeakMap<HTMLElement, Record<string, unknown>>`), propagating scalar changes to duplicate bindings (`EC19`), supporting `Naizo.bind(root)` for dynamically rendered subtrees (`EC20`), preserving unbound fields/lists/item keys (`EC14`), validating JSON values at public setters (`EC35`), and using `Object.hasOwn()` / `Object.defineProperty` own-property writes (`EC24`, `EC38`).
  - Bound exclusively via `naizo` / `data-naizo` / `data-naizo-field` (`EC11`); skipped `password`, `file`, and button input types (`EC21`); excluded `[naizo-ignore]` / `[data-naizo-ignore]` subtrees via `closest()` (`EC23`); defaulted `contenteditable` to plain text (`textContent`, `D22`, `EC18`).
  - Bumped `_meta.updatedAt` only when serialized content changes (`EC06`), preserved stored numeric/boolean types on no-op round-trips (`EC25`) and unknown `<select>` values (`EC15`), debounced persistence (~150 ms) with synchronous cache/DOM flush on `pagehide` / `visibilitychange: hidden`, baked HTML attributes only on the export clone (`D23`), and revoked fallback Blob URLs (`EC02`). Verified with 18/18 passing tests across `tests/naizo.test.ts` and `tests/release.test.ts`.
- [ ] **M4.2 — Surgical `#naizodb` disk sync, live `file.lastModified` watch, conflict recovery, and truthful status pill UX (`D13`, `D16`, `D20`, `D24`, `D27`; `EC02`, `EC08`, `EC10`, `EC17`, `EC26`–`EC28`, `EC36`)**:
  - Queue disk writes single-flight (`EC26`); read `await fileHandle.getFile()` before writing, on window `focus` / `visibilitychange`, and via a lightweight ~2 s `file.lastModified` watch timer while `document.visibilityState === 'visible'` and a granted `fileHandle` is linked (`EC10`).
  - Escape `<` as `\u003c` when serializing `#naizodb` JSON (`EC08`); replace only the `<script id="naizodb">` block in the file text (preserving a leading UTF-8 BOM if present, and refusing to modify an existing file that lacks `#naizodb` without confirmation, `EC28`); record the disk snapshot from the exact payload written (`EC26`).
  - Normalize storage keys (`/index.html` → `/`, optional `naizo-id` / `data-naizo-id` / `_meta.id`, `EC11`), and refresh the store on cross-tab `storage` events (`EC27`).
  - On external disk updates or three-way divergence (`cache ≠ snapshot` and `disk ≠ snapshot`), perform a shallow top-level key merge (`fields[k]`, `lists[k]`, `custom[k]`) against the last disk state so concurrent edits to different keys both survive, guard `document.activeElement` against mid-keystroke overwrite, and on same-key collisions let disk win while saving the pre-merge browser state under `naizodb_backup_<key>` with a 1-click **`↺ Restore`** action in the status pill (`EC17`).
  - Update the Shadow DOM status pill (`#__naizodb_host__`) to distinguish **amber** (`Browser Cache · Click to Link Disk`) whenever edits are not yet written to disk from **green** (`Synced to Disk`) after `writable.close()` completes (`EC36`), and add **`📋 Copy`** (`Naizo.copyJSON()`) and **`× Unlink`** (`Naizo.unlink()`) actions.
  - Keep full HTML serialization (with attribute baking and `[data-naizo-runtime]` / auto-template stripping) in `Naizo.exportHTML()` and the Blob download fallback, calling `URL.revokeObjectURL()` (`EC02`).
