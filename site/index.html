Self-persisting HTML for human & AI flows.

naizo.js turns any single .html file into a self-saving application – from custom dashboards, studios, and personal trackers to interactive specs and creative micro-tools – with state stored in a built-in JSON block (<script id="naizodb">) shared between your browser and AI agents on disk.

01 / CONCEPT

Why Naizo?

A single .html file can be almost anything: a custom tool tailored to your workflow, a visual canvas, an inventory studio, a project board, or an interactive notebook crafted in seconds with an AI agent. Yet plain HTML has two persistent limits: edits in the browser vanish on refresh, and saving to localStorage traps your data inside the browser where CLI or IDE agents on disk cannot see it.

In Japanese, naizō (ないぞう) has two homophonous meanings – and naizo.js provides both with a single <script> tag:

内蔵 – Built-In #naizodb in <head>

Every HTML document houses its own 2-space indented JSON database ({ _meta, fields, lists, custom }) inside <script id="naizodb" type="application/json">. <body> stays a clean template; #naizodb holds the canonical data.

内臓 – Internal Organs naizo.js runtime

Reactive field bindings (naizo="key"), a declarative list repeater (naizo-list="name"), surgical in-place disk writes (⌘S / Ctrl+S), and a ~2 s file watcher that 3-way merges external agent edits without interrupting focused inputs.

02 / ARCHITECTURE

The Human Browser ↔ #naizodb ↔ Local File ↔ AI Agent Loop

Humans interact with rendered HTML controls in the browser; AI agents read and edit structured JSON on disk. naizo.js keeps both sides synchronized without a backend server:

  • 1. Browser DOM

    Edit inputs, contenteditable blocks, or [naizo-list] rows. O(1) event capture updates the in-memory store and localStorage immediately.

  • 2. #naizodb Store

    Unbound fields, unbound lists, and extra item keys (such as id or estimate) pass through untouched. Per-key fnv1a: hashes track baseline state.

  • 3. Local .html File

    Pressing ⌘S / Ctrl+S links the file via the File System Access API and surgically updates only the <script id="naizodb"> block – keeping git diff clean.

  • 4. CLI / IDE Agent

    When an AI agent edits #naizodb on disk, naizo.js detects file.lastModified within ~2 s, merges unrelated keys, protects document.activeElement, and backs up same-key collisions to ↺ Restore. 

Browser DOM  ──(O(1) input + ⌘S surgical write)──►  <script id="naizodb"> in plan.html
             ◄──(~2 s watch + 3-way key merge)────  Edited on disk by CLI / IDE Agent

04 / QUICK START

Three Steps & CDN Snippets

No Node.js, bundler, or backend server is required:

  • 1. Embed #naizodb

    Place <script id="naizodb" type="application/json"> and the naizo.js script tag inside <head>.

  • 2. Bind Markup

    Add naizo="key" to fields and naizo-list="name" + naizo-item to repeating lists in <body>.

  • 3. Press ⌘S / Ctrl+S

    Open the .html file in your browser and press ⌘S / Ctrl+S to link it on disk (or click Save to PC in Online Mode).

1. Minimal self-persisting HTML template 
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <script id="naizodb" type="application/json">
      {
        "_meta": {},
        "fields": { "title": "Launch Plan" },
        "lists": { "tasks": [{ "done": false, "task": "Review architecture" }] },
        "custom": {}
      }
    </script>
    <script src="https://cdn.jsdelivr.net/npm/naizojs@latest/dist/naizo.js" defer></script>
  </head>
  <body>
    <h1 contenteditable="true" naizo="title">Launch Plan</h1>
    <div naizo-list="tasks">
      <div naizo-item>
        <label><input type="checkbox" naizo="done" /></label>
        <label><input type="text" naizo="task" /></label>
      </div>
    </div>
  </body>
</html>

06 / CONTRACT

Declarative HTML Attributes & window.Naizo API

Every attribute supports both concise naizo / naizo-* syntax and HTML5-compliant data-naizo / data-naizo-* aliases (for example, naizo="key" or data-naizo="key").

Attribute (or data-*) Target Element Behavior
naizo="key" <input>, <textarea>, <select>, <details>, [contenteditable], leaf Binds element state to fields["key"] (or item property inside [naizo-item]).
naizo-list="name" <div>, <ul>, <tbody> Declares a repeating list bound to lists["name"] and appends + Add Item.
naizo-item Direct child of [naizo-list] Marks a repeating row/card with hover ↑ ↓ × controls and WeakMap pass-through keys.
naizo-template <template> in list Optional explicit blueprint for new items (auto-inferred from first item when omitted).
naizo-add="name" <button> Appends a new blank item to [naizo-list="name"].
naizo-remove <button> in item Removes the enclosing [naizo-item] row.
naizo-move="up|down" <button> in item Moves the enclosing [naizo-item] row up or down.
naizo-no-controls [naizo-list] Disables automatic injection of + Add Item and row toolbars.
naizo-ignore Any element Excludes element/subtree from state binding while preserving it in exported HTML.
naizo-strip Any element Excludes element/subtree from state binding and strips it from auto-templates and exported/downloaded HTML (⬇ Save to PC).
naizo-id="scope" <html> or <body> Optional document scope identifier to isolate storage keys on localhost.
naizo-mode="online|local|auto" <html> or <body> Overrides automatic Local Mode vs. Online Mode detection.
naizo-manual <html>, <body>, or <script> Opts out of automatic boot so you can call Naizo.init() manually.

Browser & Mode Capability Matrix

How naizo.js adapts across Local Mode and Online Mode while keeping the status pill truthful about storage durability.

Mode & Browsers Status Pill & Action Persistence, Sync, & Recovery
Local Mode (Live Disk)
Chrome, Edge, Brave, Arc on file:// or localhost 		Browser Cache · Click to Link Disk
↓ after linking
Synced to Disk 		⌘S / Ctrl+S links or saves immediately; surgical <script id="naizodb"> in-place write; immediate disk flush on tab switch; IndexedDB handle persistence; ~2 s file.lastModified watch; 3-way shallow key merge with ↺ Restore backup.
Online Mode (Web Host)
All modern browsers on GitHub Pages or https:// 		Saved in Browser
Actions: ⬇ Save to PC · ↺ Reset 		Instant localStorage persistence + cross-tab storage merge; ↺ Reset with inline Shadow DOM confirmation and ↺ Restore undo backup; ⬇ Save to PC (Naizo.downloadHTML()) rewrites relative naizo.js paths to npm CDN and strips naizo-mode="online" so downloaded .html files run in Local Mode on a PC.
Local Mode (Fallback)
Safari & Firefox on file:// or localhost 		Browser Cache · Click to Save HTML
Action: 📋 Copy 		Full reactive bindings, [naizo-list] repeater, and localStorage cache; 1-click 📋 Copy (Naizo.copyJSON()) to copy #naizodb JSON to clipboard; 1-click clean .html snapshot download via Naizo.exportHTML().
