naizo.js

Self-persisting HTML for human & AI workflows.

naizo.js is a zero-dependency JavaScript library that turns any single .html file into a self-saving local-first application – from custom dashboards, interactive studios, and personal trackers to calculators, notebooks, specs, and more.

Your data lives in a built-in JSON block (<script id="naizodb">) right inside the HTML file, so humans in the browser and AI agents on disk can read, build, and update the exact same file without a backend server.

01 / CONCEPT

Why Naizo?

A single .html file is one of the simplest, most versatile formats on a computer. Whether you write one by hand with a few HTML tags or generate one in seconds with an AI agent, a single file can be a custom dashboard, an interactive studio, a personal tracker, a calculator, a notebook, or a living specification – far richer than plain Markdown, with zero build tools or framework setup.

Yet standard HTML has two everyday limits: edits in the browser vanish on refresh, and saving to localStorage traps your changes inside your browser profile where the .html file on disk – and any CLI or IDE AI agent working alongside you – cannot see them.

In Japanese, naizō (ないぞう) has two meanings that share the same pronunciation – and naizo.js brings both to standard HTML with a single <script> tag:

内蔵 – Built-In Everything inside the HTML file

Everything lives inside one self-contained .html file. Your document carries its own clean, readable JSON database (#naizodb) right inside <head> alongside its layout and styles – no backend server to host and no separate .json sidecar file to manage.

内臓 – Internal Organs Working organs for static HTML

Plain HTML markup is a static skeleton. naizo.js gives it working internal organs: fields and text blocks that remember what you type, repeating lists you can add to or reorder on the fly, and two-way sync between your browser and the .html file on disk.

02 / ARCHITECTURE

One HTML File, Shared by Humans & AI Agents

Humans prefer interacting with visual controls in the browser (and writing clean, readable HTML without boilerplate); AI agents prefer reading and updating structured JSON on disk. naizo.js connects both inside a single .html file:

  • 1. Edit in Your Browser

    Type into headings, form inputs, notes, or interactive checklists just like any web app. Every change is saved immediately in the browser so you never lose work when reloading the tab.

  • 2. Clean Built-In Data (#naizodb)

    Instead of scattering state across noisy HTML attributes, your layout stays clean in <body> while your data lives in a structured JSON block (#naizodb) in <head> – easy for humans to inspect and effortless for AI agents to read or edit.

  • 3. Saved Straight to Your File

    Click the status pill in the bottom-right corner (or press ⌘S / Ctrl+S) once to link your local .html file. From then on, saving writes your updated data directly back into that file on your computer – no shortcuts to memorize, clean git diff history, and one self-contained file.

  • 4. Live Co-Editing with AI Agents

    While your file is linked, you and your AI agent (Claude Code, Cursor, Antigravity, Codex, or Gemini CLI) can work on it together. When the agent updates the file on disk, your open browser tab picks up the changes automatically within ~2 seconds without interrupting what you are typing.

                  ◄──(Auto-syncs external disk edits in ~2 s)────  CLI / IDE AI Agent or Editor
Under the Hood Technical architecture & sync guarantees
  • Template vs. Data

    <script id="naizodb" type="application/json"> holds 2-space-indented JSON ({ _meta, fields, lists, custom } with < escaped as \u003c). <body> acts as the template; form attributes (value, checked, selected) are baked into HTML only when exporting a standalone snapshot (Naizo.exportHTML() / ⬇ Save to PC).

  • Surgical Disk Writes

    In Chromium browsers (Chrome, Edge, Brave, Arc), linking a local file via the File System Access API stores the handle in IndexedDB (NaizoDB_Handles) and surgically replaces only the <script id="naizodb"> block on disk. Runtime DOM mutations from third-party libraries (Tailwind CDN, Lucide, Mermaid) never pollute your source file.

  • 3-Way Key Merge & Restore

    A lightweight ~2 s file.lastModified watcher (plus tab-focus and pre-write checks) compares per-key fnv1a: hashes across fields, lists, and custom. Unrelated human and agent edits merge cleanly, focused inputs (document.activeElement) are protected from mid-keystroke overwrites, and same-key collisions are backed up to localStorage with a 1-click ↺ Restore button in the status pill.

  • Pass-Through Data Safety

    Unbound fields, unbound lists, and extra list-item properties (such as id, createdAt, or custom metadata) are preserved in the in-memory store and per-row WeakMap so agent-authored data is never dropped when a human edits the UI.

04 / QUICK START

Build a Self-Saving HTML File in 60 Seconds

Easy for humans to write by hand, and effortless for AI agents to generate. No Node.js, bundler, or backend server is required – just standard HTML and a couple of readable attributes:

  • 1. Embed #naizodb

    Place <script id="naizodb" type="application/json"> and the naizo.js script tag inside <head>.

  • 2. Bind Your HTML

    Add naizo="key" to fields you want to persist and naizo-list="name" + naizo-item to repeating lists in <body>.

  • 3. Link & Save

    Open the .html file in your browser and click the bottom-right status pill (or press ⌘S / Ctrl+S) to link it on disk – or click Save to PC when viewing a hosted page online.

1. Minimal self-persisting HTML template 
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <script id="naizodb" type="application/json">
      {
        "_meta": {},
        "fields": { "title": "Launch Plan" },
        "lists": { "tasks": [{ "done": false, "task": "Review architecture" }] },
        "custom": {}
      }
    </script>
    <script src="https://cdn.jsdelivr.net/npm/naizojs@latest/dist/naizo.js" defer></script>
  </head>
  <body>
    <h1 contenteditable="true" naizo="title">Launch Plan</h1>
    <div naizo-list="tasks">
      <div naizo-item>
        <label><input type="checkbox" naizo="done" /></label>
        <label><input type="text" naizo="task" /></label>
      </div>
    </div>
  </body>
</html>

06 / CONTRACT

Declarative HTML Attributes & window.Naizo API

Start with simple HTML attributes; reach for JavaScript only when building custom widgets. Every attribute supports both concise naizo / naizo-* syntax and HTML5-compliant data-naizo / data-naizo-* aliases (for example, naizo="key" or data-naizo="key").

Attribute (or data-*) Target Element Behavior
naizo="key" <input>, <textarea>, <select>, <details>, [contenteditable], leaf Binds element state to fields["key"] (or item property inside [naizo-item]).
naizo-list="name" <div>, <ul>, <tbody> Declares a repeating list bound to lists["name"] and appends + Add Item.
naizo-item Direct child of [naizo-list] Marks a repeating row/card with hover ↑ ↓ × controls and WeakMap pass-through keys.
naizo-template <template> in list Optional explicit blueprint for new items (auto-inferred from first item when omitted).
naizo-add="name" <button> Appends a new blank item to [naizo-list="name"].
naizo-remove <button> in item Removes the enclosing [naizo-item] row.
naizo-move="up|down" <button> in item Moves the enclosing [naizo-item] row up or down.
naizo-no-controls [naizo-list] Disables automatic injection of + Add Item and row toolbars.
naizo-ignore Any element Excludes element/subtree from state binding while preserving it in exported HTML.
naizo-strip Any element Excludes element/subtree from state binding and strips it from auto-templates and exported/downloaded HTML (⬇ Save to PC).
naizo-id="scope" <html> or <body> Optional document scope identifier to isolate storage keys on localhost.
naizo-mode="online|local|auto" <html> or <body> Overrides automatic Local Mode vs. Online Mode detection.
naizo-manual <html>, <body>, or <script> Opts out of automatic boot so you can call Naizo.init() manually.

Browser & Mode Capability Matrix

One HTML file that adapts to where you open it. Whether you open a file locally from your computer (file:// or localhost) or host it online (https://), naizo.js adapts automatically and keeps the bottom-right status pill clear about where your changes are saved.

Mode & Browsers Status Pill & Action Persistence, Sync, & Recovery
Local Mode (Live Disk)
Chrome, Edge, Brave, Arc on file:// or localhost 		Browser Cache · Click to Link Disk
↓ after linking
Synced to Disk 		⌘S / Ctrl+S links or saves immediately; surgical <script id="naizodb"> in-place write; immediate disk flush on tab switch; IndexedDB handle persistence; ~2 s file.lastModified watch; 3-way shallow key merge with ↺ Restore backup.
Online Mode (Web Host)
All modern browsers on GitHub Pages or https:// 		Saved in Browser
Actions: ⬇ Save to PC · ↺ Reset 		Instant localStorage persistence + cross-tab storage merge; ↺ Reset with inline Shadow DOM confirmation and ↺ Restore undo backup; ⬇ Save to PC (Naizo.downloadHTML()) rewrites relative naizo.js paths to dist/naizo.min.js on the npm CDN and strips naizo-mode="online" so downloaded .html files run in Local Mode on a PC.
Local Mode (Fallback)
Safari & Firefox on file:// or localhost 		Browser Cache · Click to Save HTML
