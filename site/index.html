The Built-In Engine for Self-Persisting HTML & AI Agent Workflows

Turn static .html specs, plans, checklists, notebooks, and triage boards into self-saving applications whose state syncs between the browser DOM, <script id="naizodb" type="application/json">, localStorage, and the local file on disk.

内蔵 — naizō (Built-In / Embedded)

In-File Canonical JSON State (#naizodb)

Every HTML document embeds its own 2-space indented JSON micro-database ({ _meta, fields, lists, custom }) inside <script id="naizodb" type="application/json"> in <head>. No backend server, no separate .json sidecar, and no state trapped only in browser storage—<body> is the template and #naizodb is the canonical data.

内臓 — naizō (Internal Organs / Viscera)

Reactive Bindings & Two-Way Disk Sync

Plain HTML markup is a static skeleton. naizo.js supplies the living internal organs: O(1) field bindings (naizo="key"), a declarative list repeater (naizo-list="name"), surgical #naizodb disk writes (⌘S / Ctrl+S), and a ~2 s file watcher that 3-way merges external AI agent edits on disk.

The Human Browser ↔ #naizodb ↔ Local File ↔ AI Agent Loop

How humans in the browser and AI coding agents on disk collaborate on a single .html file without clobbering each other.

1. HUMAN IN BROWSER

Edit DOM & Press ⌘S

Check boxes, edit contenteditable headings, or add/reorder [naizo-list] items. Press ⌘S / Ctrl+S (or click Link Disk / ⬇ Save to PC).

2. BUILT-IN #naizodb

In-Memory Store + Cache

O(1) event capture updates { _meta, fields, lists, custom }, preserves unbound pass-through keys (id, estimate), and writes fnv1a: per-key hash manifests.

3. LOCAL .HTML ON DISK

Surgical Disk Sync

Via the File System Access API, naizo.js replaces only the <script id="naizodb"> block in place (\u003c-escaped) and flushes immediately when you switch tabs.

4. CLI / IDE AI AGENT

Live ~2 s Watch & 3-Way Merge

When Claude Code, Antigravity, Cursor, or Codex edits #naizodb on disk, naizo.js merges unrelated keys within ~2 s without clobbering document.activeElement (backing up collisions to ↺ Restore).

3-Step Quick Start & CDN Copy Snippets

No Node.js, bundler, or backend required—just one HTML file and a browser.

Step 1

Embed #naizodb + Script in <head>

Place <script id="naizodb" type="application/json"> and the naizo.js CDN script inside <head>. 

<script id="naizodb" type="application/json">
{
  "_meta": {},
  "fields": { "title": "Launch Plan" },
  "lists": {
    "tasks": [{ "done": false, "task": "Ship v1" }]
  },
  "custom": {}
}
</script>
<script src="https://cdn.jsdelivr.net/npm/naizojs@latest/dist/naizo.js" defer></script>
Step 2

Bind HTML with naizo="..."

Bind scalar fields with naizo="key" and repeating lists with naizo-list="name" + naizo-item (wrapping inputs in <label>). 

<h1 contenteditable="true" naizo="title">Launch Plan</h1>

<div naizo-list="tasks">
  <div naizo-item>
    <label><input type="checkbox" naizo="done" /></label>
    <label><input type="text" naizo="task" /></label>
  </div>
</div>
Step 3

Press ⌘S / Ctrl+S or Save to PC

Open your .html file and press ⌘S / Ctrl+S to link it on disk (Synced to Disk), or click ⬇ Save to PC on any hosted Online Mode app to take a portable copy offline.

Declarative HTML Attributes & window.Naizo API

Every attribute supports both concise naizo-* syntax and HTML5-compliant data-naizo-* aliases.

Short Attribute HTML5 data-* Alias Target Element Behavior
naizo="key" data-naizo="key" <input>, <textarea>, <select>, <details>, [contenteditable], leaf Binds element value/state to fields["key"] (or item property inside [naizo-item]).
naizo-list="name" data-naizo-list="name" <div>, <ul>, <tbody> Declares a repeating list bound to lists["name"] and injects + Add Item.
naizo-item data-naizo-item Direct child of [naizo-list] Marks a repeating row/card with hover ↑ ↓ × controls and WeakMap pass-through keys.
naizo-template data-naizo-template <template> in list Optional explicit blueprint for new items (auto-inferred from first item when omitted).
naizo-add="name" / naizo-remove / naizo-move="up|down" data-naizo-add / data-naizo-remove / data-naizo-move <button> Custom list add, row delete, and row reorder triggers.
naizo-no-controls data-naizo-no-controls [naizo-list] Disables automatic injection of + Add Item and row toolbars.
naizo-ignore data-naizo-ignore Any element Excludes element/subtree from state binding while preserving it in exported HTML.
naizo-id="scope" / naizo-mode="online|local|auto" / naizo-manual data-naizo-id / data-naizo-mode / data-naizo-manual <html> or <body> Storage key scoping on localhost, Local vs. Online Mode override, and manual Naizo.init() opt-out.

Programmatic JavaScript API (window.Naizo / window.NaizoDB) 

// Custom state (db.custom) & Standalone fields (db.fields)
Naizo.get('rateLimitRps');              Naizo.set('rateLimitRps', 250);        Naizo.delete('oldKey');
Naizo.getField('owner');                Naizo.setField('owner', 'Kenji');      Naizo.deleteField('flag');

// Repeating lists (db.lists)
Naizo.getList('tasks');                 Naizo.addItem('tasks', { done: false, title: 'Ship', priority: 'High' });
Naizo.updateItem('tasks', 0, { done: true });  Naizo.moveItem('tasks', 1, 0);  Naizo.removeItem('tasks', 2);

// Lifecycle, Disk Sync, Online Mode Reset, & Portable HTML Export
Naizo.bind(rootEl);                     await Naizo.save();                    Naizo.reset();
await Naizo.unlink();                   await Naizo.copyJSON();
const html = Naizo.exportHTML();        const portable = Naizo.downloadHTML('app.html');

// Events: 'naizo:hydrate', 'naizo:change', 'naizo:item'

Browser & Mode Capability Matrix

How naizo.js adapts automatically across Local Mode and Online Mode while keeping the status pill truthful about storage durability.

Environment & Mode Browsers Status Pill & Primary Action Persistence, Sync, & Recovery Capabilities
Local Mode (Live Disk Sync)
file://, localhost, 127.0.0.1, or naizo-mode="local" 		Chrome, Edge, Brave, Arc (File System Access API) Amber Browser Cache · Click to Link Disk → Green Synced to Disk (Link Disk / Resume Disk Sync / × Unlink) ⌘S / Ctrl+S links or saves immediately; surgical <script id="naizodb"> in-place write; immediate disk flush on tab switch; IndexedDB handle persistence; ~2 s file.lastModified live watch; 3-way shallow key merge with ↺ Restore conflict backup.
Online Mode (Hosted Web Apps)
GitHub Pages or any remote https:// origin (or naizo-mode="online") 		All modern browsers (Chrome, Safari, Firefox, Edge, Mobile) Green Saved in Browser + ⬇ Save to PC + ↺ Reset (when modified from initial baseline) Instant localStorage persistence + cross-tab storage merge; ↺ Reset with inline Shadow DOM confirmation and ↺ Restore undo backup; ⬇ Save to PC (Naizo.downloadHTML()) rewrites relative naizo.js paths to npm CDN and strips naizo-mode="online" so downloaded .html files run in Local Mode on a PC.
Local Mode (Fallback Export)
file:// or localhost without showSaveFilePicker 		Safari, Firefox Amber Browser Cache · Click to Save HTML + 📋 Copy Full reactive bindings, [naizo-list] repeater, and localStorage cache; 1-click 📋 Copy (Naizo.copyJSON()) to copy #naizodb JSON to clipboard; 1-click clean .html snapshot download via Naizo.exportHTML().
